# Master Test Plan

Governs `test-cases.csv` / `test-cases.json` (95 cases, generated by
`scripts/qa/generate-test-cases.mjs` — edit the script, not the
generated files, and re-run it after any change). This plan explains
the methodology, priority order, and how each scenario in §8 of the
assessment brief maps to concrete test IDs.

## Methodology

Cases were authored by tracing actual code (routes, migrations,
existing test files) rather than writing generic boilerplate. Every
case falls into one of these origins:

1. **Regression case for a real bug fixed this session** (e.g.
   AUTH-004, RLS-001, ADMIN-004, AI-002, ING-004, EXT-001/002) —
   already has automated coverage; catalogued here for traceability,
   not re-authored.
2. **Existing coverage, catalogued for the first time** (e.g. SEC-003
   portfolio-SSRF, SEC-004 open-redirect, MON-001 Sentry redaction) —
   real, passing tests that predate this assessment but had no
   structured catalogue entry until now.
3. **New case, not yet executed** ("Automation Status: New - to
   author") — a real gap identified in `01-gap-analysis.md`, to be
   authored and run in Phase 3.
4. **Blocked case** — requires access this assessment does not have
   (production DB, Vercel, Stripe/Checkly/Sentry dashboards); marked
   `NOT RUN` with the specific blocking reason, never silently
   dropped.

No case was written to pad a count. 95 is the number of genuinely
distinct, traceable scenarios this pass identified — not a target.

## Compatibility testing (§7.11) — not yet catalogued as individual cases

Browser/viewport compatibility depends on what's actually installable
in this environment. This assessment can run Playwright's Chromium
project locally (already the default for the existing 26+9 specs) and
can add Firefox/WebKit projects to `playwright.config.ts` if desired,
but has no access to real Safari-on-macOS or physical device testing.
Rather than fabricate `COMPAT-###` cases for browsers this environment
cannot exercise, compatibility status will be recorded honestly in
`docs/qa/06-test-execution-report.md` as: Chromium — tested;
Firefox/WebKit — tested if added to CI config, else NOT RUN with
reason; Safari/macOS/mobile devices — NOT RUN, environment
unavailable.

## What "Automation Status: New - to author" means operationally

These cases have real, specific expected results derived from reading
actual code — they are not placeholders. "New" means the assertion
does not yet exist as a runnable test; Phase 3 will either author it
(when safe and non-production-impacting) or execute it manually and
record the result with evidence, per the case's own `Environment`/
`Evidence Required` columns.

## Non-inflation statement

Per §21 of the assessment brief: creating this catalogue is not
sufficient for a release decision. Every case here starts as `NOT RUN`
in `test-cases.csv`. Only `06-test-execution-report.md`, populated
after real execution with real evidence in `test-evidence/<sha>/`,
can change that.
