# Feature-spec implementation audit

Audit date: 2026-08-09. The source specification was `autotime-eu-apply-feature-spec.md`.

| Phase | Status | Implementation / remaining deployment work |
| --- | --- | --- |
| 1 ATS detector | Implemented | The shared detector covers all 11 specified ATS platforms. `extractJob` records `atsPlatform`, the shared application schema retains it, and dashboard sync writes and reads `applications.ats_platform`. Production row verification remains a deployment check. |
| 2 EURES | Done pending manual secrets/deployment | `sync-eures` has bounded pagination, conservative delay, retry/backoff and idempotent upsert. Exact deploy commands, secret checklist and daily pg_cron definition are in `docs/job-ingestion-deployment.md`. |
| 3 ATS feeds | Done pending operator seed and deployment | Greenhouse, Lever, Ashby and Personio adapters implement the common interface. `scripts/seed-ats-slugs.mjs` validates and upserts an operator-reviewed JSON list into `company_ats_slugs`; a starter list and per-platform slug documentation are included. Live slug/feed validation remains manual. |
| 4 schema/dedup | Implemented | Separate `job_listings` schema, URL and title/company hashes, unique constraints, indexes, RLS, and tests. |
| 5 aggregators | Done pending manual account/credential step | Adzuna and Jooble scheduled ingestion is implemented. Missing credentials produce `disabled_missing_credentials` without failing direct ATS sync. Operators must obtain licensed keys and confirm provider terms/quotas. |
| 6 UI | Implemented | `/dashboard/jobs/browse` reuses workflow UI patterns and copies a selected listing into the existing private local-first tracked-job model. |
| 7 ATS-aware CV | Done | Canonical `CVData`, persistent editor, live ATS-safe preview, tracked-job `job_id` prefill/AI tailoring, browser text-PDF export, and non-empty PDF test. |
| 8 outreach | Done — Path B + peer amendment | Repository and sibling-workspace searches found no Apollo client or cache table. Manual same-company contact entry exists on job detail and supports recruiter, hiring-manager, and target-role peer types. Peer drafts use an informational 15-minute role/team conversation ask and prohibit application or referral asks. Editable tracking/copy/follow-up remains human-sent; there is no cross-company or open-ended people search. |
| 9 ESCO questionnaire and matching | Done for overlap-only MVP, pending official dataset import | Database taxonomy/user-profile schema, RLS, deterministic ingestion classification, explicit skill confirmation, explainable essential-skill overlap RPC/UI, CSV importer and tests are implemented. Each questionnaire round now receives accumulated skill IDs, confidence and source, prioritises low-confidence gaps, and avoids re-asking established skills. Vector matching is explicitly deferred and dormant vector columns/signatures are removed by `20260811120000_defer_esco_vector_matching.sql`; adding it later requires a versioned embedding lifecycle, backfill and quota controls. |
| 10 extension scope narrowing | Done | Web and extension share one ATS detector. Greenhouse, Lever, Ashby, Personio and EURES use reference-only capture; Workday, iCIMS and unknown sites retain selector/JSON-LD fallback. LinkedIn and other covered/restricted boards are manual-only. The widget explains the selected mode and API references are stored without DOM extraction. |

The original spec refers to an existing `jobs` table, Apollo lookup, and sponsor-register Edge Function pattern. This repository instead has a local-first `JobRecord` workflow plus a cloud `applications` table and had no Apollo implementation or prior `supabase/functions` directory. The implementation preserves that architecture, uses manual recruiter entry as the safe fallback, and does not create a competing candidate tracker.
