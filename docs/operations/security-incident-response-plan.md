# Security incident response plan

Status: security-reporting delivery BLOCKED until a synthetic report is received and acknowledged.

1. Receive reports through a published security address/form monitored by named primary/backup owners.
2. Acknowledge, assign severity, start an immutable timeline and minimize copied personal data.
3. Contain using the least destructive control: disable invitations, suspend AI usage, revoke a user/session/key, disable ingestion/payment, or rollback deployment.
4. Preserve redacted logs and evidence; never paste secrets into tickets or chat.
5. Eradicate and recover using reviewed changes, migration forward fixes and the rollback/restoration runbooks.
6. Notify affected parties/regulators when legally required; obtain legal/privacy guidance.
7. Retest the exploit and adjacent controls, document lessons and close only with evidence.

P0 examples: cross-account access, admin escalation, exposed service key, payment forgery or destructive privacy failure.
